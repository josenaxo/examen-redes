1. Diseño de red y tabla VLSM

La red une tres sedes (Santiago, Valparaíso y Concepción) con un proveedor de Internet (ISP) y con enlaces inter-sucursales Santiago-Valparaíso (serial) y Valparaíso-Concepción (Gigabit). Se usa el bloque privado 172.16.40.0/22 (RFC 1918), dividido con VLSM: las subredes se asignan de mayor a menor cantidad de hosts y cada una recibe el prefijo más pequeño que cubre su demanda (hosts = 2h - 2).

2. Enrutamiento estático + OSPF: por qué se combinan

OSPF (proceso 1, área 0, Router-ID 1.1.1.1 a 4.4.4.4) anuncia automáticamente todas las redes internas y recalcula los caminos si un enlace cae, sin intervención manual. Las interfaces LAN son passive-interface para no enviar paquetes OSPF hacia los equipos de usuario.

Los enlaces con el ISP tienen costo OSPF 100. Así el tráfico entre sedes prefiere los enlaces inter-sucursales (por ejemplo, Santiago-Concepción por Valparaíso cuesta 66 contra 201 por el ISP).

Las rutas estáticas controlan la salida a Internet: cada sucursal tiene una ruta por defecto hacia su ISP (distancia administrativa 1) y una ruta flotante de respaldo por el enlace inter-sucursal (AD 210), que solo se instala si cae la principal. El ISP tiene una ruta resumida 172.16.40.0/22 con AD 250 como último respaldo. La combinación entrega convergencia automática dentro de la empresa y control explícito y predecible sobre la salida a Internet.

3. SSH y seguridad básica

  • Banner MOTD de acceso restringido y contraseñas guardadas con hash (enable secret, username ... secret) más service password-encryption.
  • Usuario local con privilegio 15 y login local en consola y en las líneas VTY.
  • SSH versión 2 con llaves RSA de 1024 bits y dominio apexlogistica.local. Las líneas VTY solo aceptan SSH (transport input ssh), por lo que Telnet, que viaja en texto plano, queda bloqueado.
  • exec-timeout de 5 minutos para cerrar sesiones inactivas.

SSH cifra toda la sesión, autentica al servidor con su llave pública y protege las credenciales del administrador cuando gestiona los routers en forma remota desde la PC ADMIN o desde otra sede.

4. Administración centralizada de usuarios (Active Directory / Samba, GPO)

Un servicio de directorio (Microsoft Active Directory Domain Services, o Samba configurado como controlador de dominio compatible con AD) guarda en un solo lugar las cuentas, grupos y equipos de las tres sedes. Esto permite:

  • Inicio de sesión único: el mismo usuario y contraseña en cualquier sede.
  • Altas y bajas inmediatas: al deshabilitar una cuenta, el acceso se corta en toda la empresa.
  • Políticas de grupo (GPO) aplicadas de forma uniforme: complejidad y caducidad de contraseñas, bloqueo de cuenta, bloqueo de pantalla, restricciones de software y mapeo de recursos.
  • Auditoría centralizada de accesos y cumplimiento de mínimo privilegio mediante grupos.

El controlador de dominio usará la IP reservada 172.16.40.132 en la red de servidores y depende del DNS para que los clientes lo encuentren.
